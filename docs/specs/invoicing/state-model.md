# Invoicing — State Model

Job pricing proposals, invoice-backed Revenue, document creation, and link visibility are distinct processes. A selected Invoice is the authoritative Revenue source; immutable document content never recomputes from the Job after creation. Current actual costs and tracked time remain editable. DATA-* owns persistence; UX-* owns presentation.

## States and transitions

| ID | State/process | Entry, event, guard, result and failure | Persistence / terminal behavior |
| --- | --- | --- | --- |
| STATE-01 | Job pricing | Backfill active legacy Job under DATA-09; new Job uses component pricing. Unknown Labor means an incomplete pricing proposal, not zero. Explicit zero Labor has its own no-Labor-&-Services confirmation and can coexist with positive billable charges. Once an Invoice is selected, its saved subtotal remains authoritative even if the proposal later becomes incomplete. Restored legacy Job enters pricing review before document creation; existing financial totals remain readable. Explicit owner review confirms nonnegative component pricing atomically, then clears review. Failed review leaves old totals untouched. | Job-owned pricing revision and migration/review status; no automatic destructive resolution. |
| STATE-02 | Unsaved preview | Share FAB or Generate new reads current Job/settings; choose default type under UX-04, allow type switch. Required-data gaps block creation but not Job editing. Back dismisses without assigning number or link. Changes/refetch rebuild live preview. | Transient; no persisted document. |
| STATE-03 | Creating | Explicit Create & Share submits preview source fingerprint, type, timezone and retained request key. Complete/Paid finalization creates an Invoice without requiring sharing. Lock/validate authoritative source under DATA-05. Matching source commits number/content/link once. Stale source returns stale result and requires renewed preview/action. Missing required data returns field failures. Network timeout has unknown commit outcome; retry the same request key before a new creation request. | Atomic operation: either no document or one complete document; never expose partially saved content. |
| STATE-04 | Saved snapshot | Creation succeeds or prior operation is recovered; open share sheet once while foreground. Cancellation/backgrounding never removes snapshot. Reopening via Docs is read-only. New Job edits affect only a later unsaved preview. Repeated existing Share opens sharing without creation. | Durable until account deletion; type, dates, number/content immutable. |
| STATE-05 | Invoice payment status | The selected revenue Invoice follows Job Paid/Unpaid changes. Other Invoices retain their last persisted payment status when the Job changes. Estimates have no payment status. A document's badge and Total/Amount Due label use the same stored status. | Mutable display control stored separately from immutable payload. Downloaded PDF captures that stored status at generation time. |
| STATE-06 | Sharing | Owner opens sheet from saved preview. Enabled link destinations hand off only after fresh owner/source eligibility read. User decides whether to send. Unavailable destinations use UX-07 fallback; unknown/sent/cancelled platform results do not mark document delivered or change Paid. Cancel returns to saved preview. | Transient; document remains Saved. |
| STATE-07 | PDF requested | Only explicit Download PDF enters generating. Fresh owner read captures snapshot plus current payment projection; device renders same HTML to temporary PDF, then opens native sheet. Duplicate taps coalesce while generating. Failure returns to sheet with retry; no new document/number. Cancellation retains snapshot; temporary artifact follows DATA-12 cleanup. Process termination allows a fresh explicit request, never background regeneration. | No persisted PDF workflow, hosted object, worker or server generation. |
| STATE-08 | Archive/link controls | One versioned Archive & Disable Link control archives and disables the link together; unchecking restores visibility and enables the existing token. Archived documents cannot have enabled links. Controls cannot change snapshot content. Job Edit stages controls until Done; cancellation discards the draft. Selecting a different revenue Invoice archives/disables the previous one but preserves the chosen Invoice's existing controls. Failed/concurrent saves refetch authoritative state and show retry rather than false success. | Durable control; archived documents are link-disabled. An archived Invoice may remain selected as the Revenue source. |
| STATE-11 | Invoice-backed Job Revenue | During rollout, new and historical Jobs stay unadopted until explicit invoice-backed finalization, replacement or revenue selection. Flag-off clients retain legacy Complete/Paid on unadopted Jobs; no migration auto-selects a document or changes Revenue/links. Finalization uses the selected Invoice snapshot, or creates one if none is selected. Explicit selection cannot be cleared without selecting another Invoice. Only Invoice documents can be selected. | Job Revenue is the selected Invoice's immutable pretax subtotal. Current direct costs and tracked time continue to recalculate Net earnings and Net/hour. |
| STATE-12 | Financial finalization and paid replacement | Complete/Paid opens final review. With no selected Invoice, confirmation atomically creates/selects an Invoice and applies the requested status; with one selected, confirmation uses its saved total. Sharing is optional. Replacing a source is explicit. On a Paid Job, a different total requires confirmation of exactly the new amount; cancellation preserves the previous selection and Paid status. Equal totals require no additional confirmation. | Invoice creation, default-markup solidification, source selection, previous-link disablement and requested status change commit together or roll back together. |
| STATE-13 | Markup solidification | Invoice creation copies the current business markup to materials that have no explicit override, preserving existing explicit values including 0%. Estimate creation does not copy defaults into overrides. Clearing an override resumes the current business default for future invoice calculations but cannot rewrite the selected Invoice or Job Revenue. | Current default is materialized only as part of successful Invoice creation; immutable snapshots remain unchanged. |
| STATE-09 | Job deletion/restoration | Delete Job atomically makes every public document unavailable and records disabled links. Keep owner snapshots recoverable. Restoring an excluded legacy Job enters STATE-01 review; document links stay disabled until owner explicitly enables them after Job restoration. Review blocks new creation, not historical owner preview. | Soft-deletion recovery; no implicit link reactivation. |
| STATE-10 | Account deletion | Revoke document access before/with owner deletion; cascade snapshot/default/counter/link data. Failure keeps public links revoked and allows existing delete-account retry. No public data remains via first-party storage/cache paths. | Terminal; no recovery or PDF recall claimed. |

## Events, guards and concurrency

- Creation is authenticated, owner-scoped and allowed on any active Job if DATA-04 readiness passes. Public token possession never authorizes writes, private reads, creation or PDF generation on an owner's device. Finalization is the only new-client path to Complete/Paid, including direct status-sheet entry points.
- Same owner/request key with same source/type returns the committed document; reuse with a different intent is rejected. A fresh request after reviewing changes is a different creation. Never interpret a share cancellation as a new-document request.
- Snapshot creation and Job/cost/settings changes serialize with compatible locking or revision checking: the saved output must equal the last preview the user approved. Settings mutations must participate in source fingerprints even if they do not touch jobs.updated_at.
- Paid state at creation/read is captured consistently with immutable totals. A simultaneous payment change may change projection on the next read, but must not create mismatched badge and Total/Amount Due labels within one render.
- Serializing owner/type counters avoids duplicate numbers across Jobs/devices; committed numbers are never reused. Exact sequence gaps after failed allocation are not promised absent transaction proof.
- Link controls and deletion must win on fresh public resolution before HTML or metadata/image generation. A stale cache must not bypass revocation. A page already displayed or an externally cached preview may remain visible.
- Revenue selection and Job Edit control changes use source-id/control-revision compare-and-set checks. A stale save or concurrent selection rolls back all requested Job changes. Once a Job has adopted an Invoice, older clients cannot bypass invoice-backed finalization with a direct Paid/Complete write.
- Only the selected Invoice payment status changes with the Job. Selecting a different Invoice on a Paid Job compares immutable full totals; confirmation is checked against the new total, while Revenue and collected projection remain pretax.
- Editing/reassigning/deleting a cost or Session recomputes current component pricing for affected Jobs; no saved document content changes. The migration compatibility path is defined by DATA-09/10.

## Recovery and verification

Offline: cached owner content can be viewed with an explicit stale-status notice, but create/link sharing/PDF/control writes wait for a successful fresh read. No offline mutation queue or hidden generation is introduced. Restore a retained unknown-outcome creation intent on app restart and reconcile by its idempotency key before allowing another creation; resolved saved documents are discoverable in Docs even when the share sheet never opened.

Unauthenticated/session-expired owner calls stop and use existing reauthentication; never fall back to public token data for owner actions. Backgrounded native destination handoffs remain user-controlled. Back during PDF generation may leave a temporary file, which cleanup removes after handoff returns or on next launch.

- Materials without an explicit markup resolve the current business default in Job revenue and unsaved document snapshots. A default-setting change reprices existing Jobs; an explicit override (including 0%) remains fixed. Clearing the override resumes the current default. Issued snapshots are never repriced.
