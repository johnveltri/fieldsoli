# Invoicing — Test Contract

This is required implementation evidence, not a report of tests already run. The main risks are changed economic history, incorrect customer totals, duplicate invoices, private-data publication, ineffective link revocation and inconsistent native/browser/PDF output. Use the cheapest real layer proving each boundary; mocks cannot prove RLS, platform handoff or printing.

## Fixtures and boundaries

Two synthetic owners with documents of both types, different counter histories, different business defaults and costs. Include direct/Session/Inbox materials, deleted costs/Sessions/Jobs, null/zero Revenue, confirmed-no-Revenue Paid Job, partial compatibility rows, old-client edit payloads, restored negative residual, and same Job's invoices with different totals. Use only synthetic names/addresses/phones/emails in tests; production evidence remains aggregate-only.

Pin clock/timezone and UUID generation; race tests use explicit synchronization rather than timing guesses. Network fault injection distinguishes definitive precommit failure from unknown commit outcome. RLS tests run anon, ownerA, ownerB and server roles against actual local schema, not mocked clients. Lockfile/clean SDK-compatible build verifies dependencies; rendering/device fixtures include non-ASCII text and descriptions long enough to span multiple pages.

## Required evidence and gates

| Gate | Required checks | Blocking failures |
| --- | --- | --- |
| Before merge | TEST-01..17 automated layers; docs traceability; local migration/legacy API proof; focused mobile tests plus appropriate mobile/API/typecheck/marketing validation; no runtime evidence claimed from docs alone. | Changed financial history, missing rule coverage, duplicate docs, private-data exposure or unverified platform architecture. |
| Before deployment | Fresh aggregate migration check, staged financial before/after diff, RLS/grants/security review, TEST-13/14 public access/cache proof, TEST-17 capacity/eligible-plan review, safe server env configuration. | New active negative residual, tenant leakage, stale cache revocation, unsupported renderer, unexpected paid dependency. |
| Before native submission | iOS/Android dev/release builds, TEST-09/10/11/16 real-device proof, required schemes/config and SDK pins, no unintended permission/share-extension addition. | Broken preview/PDF/composer, inaccessible controls, keyboard/safe-area regressions or build mismatch. |
| Before public release | Deployed website/back-end version compatibility, stored render-version support, production smoke with synthetic owner, native availability/processing gate, documented migration/export/deletion/rollback checks and product-context closeout. | Readiness evidence absent, quota/policy incompatibility, broken old-client access, disabled links readable. |

Commands are finalized in plan.md against repository scripts. Manual cases exist because OS composers, installed destination apps, WebView engines, VoiceOver/TalkBack and native printing cannot be proven by Jest mocks. Save representative screenshots/PDFs, platform/version notes, assertions and pass/fail outcomes in implementation evidence; do not infer successful sending from handoff callbacks.

## Deferred proof

No payments, receipts, partial balances, branding, signatures, jurisdiction tax correctness, mail delivery/read receipts, browser one-click server-generated PDF, or external-cache recall are implemented or claimed. Their absence follows spec.md; test scenarios must not introduce these features.
