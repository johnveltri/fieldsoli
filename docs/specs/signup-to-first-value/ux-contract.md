# UX contract

Primary user: a new tradesperson on a phone, often interrupted. Successful exit: useful Home and existing real-job capture, not a setup survey. iOS/Android; return-user sign-in and recovery remain reachable.

| ID | Surface and exact behavior/copy |
|---|---|
| UX-01 | Explicit Create account entry opens signup. Email, Password, show/hide, existing legal checkbox and links, Create account; returning action Sign in. Preserve existing legal text pending publication/version verification. No name or confirmation fields; email/password autofill and safe keyboard navigation. Signup controls are never hidden behind intro completion. |
| UX-02 | Verification heading “Check your email”. Body “Enter the verification code for {email}.” Field “Verification code”. Actions “Verify email” (primary; disabled until code is nonblank), “Resend email” (outlined secondary), and the standard upper-left Back control. Back returns to sign-in with the email retained, where email editing and password recovery remain available. Success moves directly through legal resolution to Home. Announce status without echoing the code. |
| UX-03 | Wrong/expired code: “That code is invalid or has expired. Check the code or request a new one.” Network: “Could not verify your email. Check your connection and try again.” Resend success: “If this email needs confirmation, check your inbox for a code or confirmation link.” Rate limit: “Please wait before requesting another code.” Uncertain signup: “We could not confirm whether your request completed. Check your email or try signing in.” No raw provider messages, account enumeration or false delivery guarantee after failure. |
| UX-04 | Legal loading: “Checking your account…”; read failure without valid cache: “Could not check your account. Try again.” Actions Retry / Sign out. Missing evidence: “Review and accept the terms to continue.” Real version change uses existing updated-terms wording. Preserve links, explicit checkbox, save failure/retry and user/version isolation. |
| UX-05 | Home heading exactly “Start with your first job.” Body exactly “Keep time, materials & expenses with the work. Add a job now and fill in details as you go.” Button exactly “Create my first job”. Existing capture opens; no sample job or silent business write. Existing saving/error/retry remains; loading/fetch failure is not empty. |
| UX-06 | Retain the existing blocking optional analytics choice before Home, with its current Allow analytics / No thanks actions and disclosures. Owner superseded the post-job card. |
| UX-07 | All surfaces support screen-reader labels/state, logical focus, paste/code autofill, text scaling, small screens/tablets, safe areas and keyboard avoidance. One native semantic code field rather than six focus traps. Respect reduced motion; no forced animation. Visible touch targets use existing accessible platform sizing. Code length derives from verified provider configuration, not an unverified six-digit assumption. |

Navigation: intro recovery/session precedence remains. Back/change-email never silently submits. In-app code is primary; legacy browser links remain supported, and app without session offers sign-in. A code read on another device is entered in the requesting app; no guarantee that an arbitrary browser becomes signed in. Do not auto-open Home until required legal resolution succeeds. Password recovery stays distinct from signup verification.

Component decision: reuse FieldSoli typography/tokens/buttons plus native TextInput, compared with custom segmented inputs (extra focus/paste burden) and external OTP/onboarding SDKs (unneeded dependency). The existing analytics modal stays before Home. Visual review in ChatGPT is required before release; no Figma synchronization.

Recovery: restore the email/code-entry destination for 24 hours without storing code/password. Unconfirmed sign-in opens verification; sign-in shows a small Continue email verification link only for the known pending email; merely entering a valid email adds no extra action. Initial/live auth links take precedence; delayed storage reads cannot overwrite a form the user has started. Upper-left Back retains the target email on sign-in. Change email and Reset password are removed from verification.
