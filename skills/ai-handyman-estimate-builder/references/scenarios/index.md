# Residential handyman scenario index

Choose the route that matches the contractor’s description. A larger project can contain many tasks; confirm the contracted portion before bringing any into the estimate.

| What the contractor brings | Where to start |
|---|---|
| A room, a remodel, a new structure or a multi-visit goal | [27 larger projects and their linked work packages](projects.md) |
| A particular component or trade | [42 task families with examples and links back to projects](tasks.md) |
| A model to install, replace or connect | [20 appliance installation branches](appliances.md) |
| A symptom, failed system or possible specialist call | [18 homeowner calls and their diagnostic or trade handoffs](calls.md) |
| A marketplace booking, short visit or unusual item | [20 marketplace requests and the scope question each raises](marketplace.md) |
| A close match to a detailed interview | Choose the relevant detailed playbook below. |

For a labor-only installer, start at the named task and confirm prerequisites the owner or GC supplies. For a qualified trade specialist, start at the symptom or system and ask about adjacent work and finish handoff. For a remodel lead, start at the project and assign each relevant work package and dependency. For a property-maintenance contractor, group by address, priority, access and visit. Use the contractor’s actual role on this job.

For any priced request, use the [pricing evidence guide](../pricing/guide.md) alongside the selected playbook. The [work package directory](../pricing/work-packages.md) identifies the unit, cost inputs and trade handoffs for the indexed task families.

## Extend the library

Add a heading to the closest file or create a specialty file and link it above. Start with a contractor utterance and the promised finish. Record activation clues, a decision-changing question, two plausible answers and the exact estimate edit for each. Include an overlooked interface, a question to skip and what would make it relevant. Identify which checks can happen before quoting, which facts require exposure and where the contractor would stop. Add a test exchange with the expected edits and an over-questioning example. Add persona-specific guidance alongside the branch where it changes the question. A new role or trade needs no change to the interview workflow.

When adding a project, link each relevant task and add the reciprocal project link under that task. Record at least one dependency or handoff that changes the estimate. For an appliance variant, record what the selected model changes at the site. Keep brief index entries distinct from tested interview playbooks.

The [research notes](research.md) document sources, U.S. scope and limits of the marketplace evidence.
